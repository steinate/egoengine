## 已发现的渲染问题

旧 Worker 渲染使用 `RayTracedLighting`，每个源帧建立新的 avatar prim，
将该帧蒙皮点、物体位姿和相机同时提交，再等待渲染完成。
新机器之前改成了 1280×720 PathTracing 64 SPP，并曾同时启动六个 Isaac
进程，导致 CPU 初始化争用和不必要的渲染开销。

另一个复用 avatar prim、原地更新网格点的加速实验出现 GPU 网格滞后。
第 1489 帧中物体已抬起，手却留在较低的位置；CPU 物体位姿误差仍为 0。
与相同姿态的正确参考图比较，旧实验平均像素绝对差为 58.63/255。
逐帧建立新 prim 的 `preview-fast-draw` 对照图则与参考图像素一致。
这些是当次场景的实测结果，不能推广成对所有 USD 动态网格的判断。

## 当前调试默认值

- 640×360、实时 RTX、关闭时序抗锯齿，单个 GPU 渲染进程。
- 保留逐帧新建人体 prim 和等待渲染完成的同步步骤。
- 先抓取末帧、首帧、末帧，比较两次末帧 RGB；失败停止。
- 默认每 3 个源帧采样一次，包含末帧，三路采用相同源帧和保持时间。
- 使用恒定帧率图片序列编码，避免 VFR 转 CFR 提前显示下一姿态。
- 视频明确标记 `sampled debug`，不是逐帧 15 fps 的渲染结果。
- 轨迹、动画与脚本哈希，实际渲染器、分辨率、采样点、耗时均写入验证 JSON。

```bash
bash "$PAIR_ROOT/human-natural-v4/render_debug.sh"
# 调查快速动作或逐帧接触时：
EGO_DEBUG_STRIDE=1 bash "$PAIR_ROOT/human-natural-v4/render_debug.sh"
```

新机器跳帧检查通过：ego 重复末帧平均像素差 1.642/255，正面 0.641/255，
物体位置误差 0 m。RGB 重复性只是发现滞后的检查，仍需人工检查抓取、放置、
抬托盘画面；不能用 CPU 位置误差或重复图像替代全部视觉验收。
`test_debug_timing.py` 在本机和新机器实际调用 ffmpeg，解码三视角视频，
验证每个输出帧确实展示同一源帧，包括末尾非等长采样区间。
